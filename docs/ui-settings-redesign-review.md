## 当前问题

| 问题 | 代码证据与触发路径 | 影响与改版方向 |
| --- | --- | --- |
| 字号被三层硬限制 | `AppearanceEditor.tsx:151` 的 `RangeControl` 只有滑块和只读 `output`；设置基础字号在 `:245` 限制 12–20。`config.ts:882` 与 Rust `config.rs:1713` 再次校验同一区间。 | 用户不能输入 24、32 或小于 12。不能只改滑块，要同步输入、导入与后端。 |
| 基础字号覆盖不完整 | `Settings.css:538/606/642`、`AppearanceEditor.css:139/157/164` 等大量使用固定 9、10、11 px，而非基础字号比例。 | 放大基础字号后，一些提示、字段标签和数值仍很小。新的字号系统需覆盖正文、控件和帮助文本。 |
| 页面切换对新建/已有命令语义相反 | `Settings.tsx:256` 的 `settleEditorForNavigation` 对已有对象调用 `applyEditor`，对新建对象删除草稿；`:742` 切换分类直接调用。自动保存 effect 在编辑器关闭后会保存草稿。 | 已有命令的未确认修改可能随切页写入，新命令则被直接丢弃。提议显式保存、离开时统一询问保存/放弃/继续编辑。 |
| 离开外观页会丢失未保存皮肤编辑 | `AppearanceEditor.tsx:284–285` 工作副本保存在组件局部状态；`Settings.tsx:1379` 仅在当前页为外观时挂载；`changeSection` 不检查主题修改。 | 编辑后切到通用再回来，工作副本重建。应把主题草稿交给页面状态管理，并保护导航。 |
| 切换保存模式会一起写入已有草稿 | `Settings.tsx:867` 将整个 `draft` 加上新开关值后直接调用 `save_app_config`。 | 用户只想改保存策略，其他尚未明确确认的修改也可能生效。模式切换前应处理未保存改动。 |
| 错误反馈可能在视区之外 | `Settings.tsx:1393–1394` 在所有页面内容之后显示错误；没有聚焦错误字段或滚动错误区域。 | 长表单保存失败时，用户可能只看到按钮恢复。使用字段旁校验与常驻状态条；错误保留到解决。 |
| 删除弹层缺少键盘隔离 | `Settings.tsx:1398` 起使用普通 div/section，虽声明 `aria-modal`，但背景不 inert，也未实现焦点循环。 | Tab 可进入背景控件；语义声明不会自动生成模态行为。使用原生 dialog 或完整的焦点管理。 |
| 窗口关闭没有待保存状态检查 | `Settings.tsx:371` 直接调用 `hide_settings`；后端 `launcher.rs:790` 只是隐藏窗口。 | 未保存数据不一定立即丢失，但用户容易把关闭理解为已保存，退出进程后草稿无法恢复。关闭前明确处理修改。 |

布局待实机核验：当前设置窗口最低宽度为 680 px；主题控件单列断点却设为 650 px，因此合法的最窄窗口仍使用双列控制组。还需检查 680×520、Windows 125%/150% 缩放和长路径。`.settings-layout aside` 也会匹配嵌套预览中的 aside，存在样式污染风险。以上是基于结构的风险，不声称已在运行中的 Suo 完整复现。

## 数值调节：本轮已确认方向

用户明确希望设置和皮肤中的文字大小等参数能调得更大或更小。当前具体范围：

| 参数 | 当前 UI / 校验范围 | 设计处理 |
| --- | --- | --- |
| 设置基础字号 | 12–20 px | 常用滑块保留 12–20；精确输入演示 1–255，允许 8、24、32 等值，提示而不静默截断。 |
| 搜索框字号 | 12–24 px | 落地时也采用滑块与合法范围分离。 |
| 普通/选中主字号 | 12–20 px | 同上；布局高度和换行需一并检查。 |
| 普通/选中次字号 | 10–18 px | 同上；低可读性只提示。 |
| 行高、图标、窗口宽高、圆角 | 各字段已有独立边界 | 分别检查真实布局与存储约束，不用一个范围替代所有字段。 |

原型的 255 来自 `u8` 字段可表达的上界；正式版本已在配置 v19 同步放开字号与对应校验，也不代表所有参数都应采用该上界。图片大小/解码、协议、脚本超时等既有安全限制不属于本次数值开放范围。

## 三个视觉方向

- A 简洁原生：浅色导航、分组列表、独立命令编辑对话框。偶尔修改设置时最轻松。
- B 分栏工具：固定导航、命令列表与编辑区并排、正文独立滚动、编辑操作常驻。推荐用于频繁管理命令。
- C 深色改良：保留深色及折叠列表，减少装饰与重复提示。迁移成本较小。

三种方向采用相同的示例数据。脚本、网页搜索和翻译从“命令与服务”中展开为直接入口；没有新增平台能力。外观中将选择预览与应用分开，并保持搜索/设置两个 scope 独立。

提案中的“命令明确保存”“普通设置自动保存”“皮肤保存与应用独立按钮”等属于待评审的流程调整，和当前统一保存策略及运行皮肤下拉框并不完全相同。选定后须更新正式需求和实现，不能直接把原型当成现有产品行为。原型只覆盖核心流程，不意味着删除主题导入导出、位置偏移、macOS Dock、脚本审批等现有能力；这些应在后续完整规格中保留。

- 图标直接复用 `assets/suo-icon.svg` 中原标识的路径，采用无底板、无光晕的透明矢量呈现，减少周围留白。通用设置可切换透明彩色、主题单色、原版底板，标题栏和侧栏同步更新；原始矢量、平台打包图标和托盘资源未修改。
